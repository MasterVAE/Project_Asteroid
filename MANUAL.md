# Project Asteroid — справочник игрока

Управляйте кораблями через Python: исследуйте пространство, добывайте ресурсы,
перерабатывайте их на заводе и стройте новые корабли на верфи. Этот справочник
описывает запуск игры, правила мира, оборудование и текущий Python API.

## Мир и координаты

В начальном мире находятся два корабля и 50 астероидов:

- **Shipyard #0** в `(0, 0)` — тяжёлая верфь без двигателей
- **Miner #1** в `(30, 0)` — легкий маневровый добытчик с буром, сканером и захватом

Оба корабля первоначально неподвижны, склады пусты. Бак добытчика заправлен
на **100 единиц топлива**. Астероиды изначально неподвижны
и появляются в случайных точках с координатами X и Y от −1000 до 1000.

Каждый объект имеет числовой ID. В начальном мире ID кораблей — 0 и 1,
астероидов — от 2 до 51. Имена задаются при создании: `Shipyard #0`,
`Miner #1`, `Asteroid #2` и так далее. Корабль можно переименовать через `ship.setName()`;
числовой ID и тип объекта при этом сохраняются.

| Величина | Значение |
| --- | --- |
| Ось X | Вправо |
| Ось Y | Вверх |
| Расстояние | Метры |
| Скорость | Метры в секунду |
| Ускорение | Метры в секунду² |
| Угол | Радианы: 0 — вправо, π/2 — вверх |
| Положительное вращение | Против часовой стрелки |
| Угловая скорость | Радианы в секунду |

Трения нет: выключение двигателя прекращает ускорение, но сохраняет скорость.

### Ресурсы

В каждом астероиде находится суммарно от **1 до 10 единиц** случайных ресурсов.
После извлечения последней единицы астероид исчезает. Одна единица любого
ресурса занимает одно место в складе.

| Ресурс | Имя для API |
| --- | --- |
| Кремний | `silicon` |
| Углерод | `carbon` |
| Железо | `iron` |
| Лёд | `ice` |
| Медь | `copper` |
| Золото | `gold` |

Сырьё из таблицы добывается на астероидах. Остальные ресурсы создаются
заводом: `water`, `hydrogen`, `oxygen`, `steel`, `glass` и `rocket_fuel`.
Полный список преобразований возвращает `Factory.getRecipes()`;
рецепты также перечислены в [RECIPES.md](RECIPES.md).
Модули устанавливаются верфью, а `rocket_fuel` автоматически заправляет бак.

## Запуск скрипта и консоль

Распакуйте архив. В его корне находятся исполняемый файл (`app.exe` для Windows,
`app` для Linux и macOS), `api.py`, `MANUAL.md` и `RECIPES.md`.
В сборках с зависимостями из исходников также есть папка `licenses`.
Запустите `app.exe` в Windows или `./app` из каталога игры в Linux и macOS.
Для управляющих скриптов нужен установленный Python 3. Создайте свой скрипт
рядом с `api.py`, чтобы работал `import api as ship`.

Выберите корабль в списке слева или нажмите на него в мире. В поле пути (script path)
к скрипту введите путь к вашему файлу, например `miner.py` для добытчика,
и нажмите Enter. Скрипт управляет выбранным кораблём. Повторный запуск
заменяет его предыдущий скрипт.

Камера следует за выбранным объектом. Без выбранного объекта клавиши WASD
перемещают камеру, если поле ввода не активно. Escape снимает фокус ввода;
вне активной консоли также сбрасывает выбор объекта.

`print()` выводит сообщения в нижнюю игровую консоль. Колесо мыши над ней
прокручивает вывод. Хранятся последние 1000 строк, старые вытесняются новыми.

Для отправки сообщения скрипту нажмите на консоль, введите текст и нажмите
Enter. Скрипт получит событие `console_message`. Стрелки ↑/↓ перебирают
историю сообщений. В полях ввода работают стрелки, Home/End, Backspace/Delete
и Ctrl/Cmd+V.


## Начало работы с API

В начале скрипта импортируйте [`api`](scripts/api.py) и один раз вызовите `start()`.

`is_running()` сообщает, остаётся ли соединение с кораблём активным.
Пример ниже предназначен для добытчика:

```python
import time
import api as ship

ship.start()

print("Корабль:", ship.getId())
print("Имя:", ship.getName())
print("Координаты:", ship.getPos())
print("Модули:", ship.getModules())

storage = ship.Storage("storage_0")
power = ship.Power("power_0")
print("Инвентарь:", storage.getStorage())
print("Заряд:", power.getCharge())

while ship.is_running():
    time.sleep(0.1)
```

### Состояние корабля

| Вызов | Результат |
| --- | --- |
| `ship.start()` | Запускает соединение с кораблём; вызывается один раз |
| `ship.is_running()` | `True`, пока соединение активно |
| `ship.getId()` | ID корабля: `int` |
| `ship.getName()` | Текущее имя корабля |
| `ship.setName(name)` | Переименовать свой корабль; непустая строка |
| `ship.saveData(data)` | Записать строку состояния скрипта в корабль для сохранения вместе с миром |
| `ship.getPos()` | Абсолютные координаты `(x, y)` |
| `ship.getVel()` | Абсолютная скорость `(vx, vy)` |
| `ship.getAngle()` | Угол корабля: `float`, радианы |
| `ship.getAngularVelocity()` | Угловая скорость: `float`, рад/с |
| `ship.getModules()` | Список имён установленных модулей |
| `ship.getMass()` | Масса корабля с грузом, топливом и захваченными астероидами; при стыковке — сумма масс пары |
| `ship.readyToConnect(ready=True)` | Разрешить стыковку со своим кораблём; `False` запрещает её |
| `ship.connect(craft_id)` | Пристыковаться к готовому кораблю на расстоянии не больше 1 |
| `ship.disconnect()` | Расстыковаться с партнёром |
| `ship.launch(path)` | Запустить скрипт по указанному пути на пристыкованном корабле |
| `ship.getConnection()` | `{"connected": id_или_None, "readyToConnect": bool}` |

```python
x, y = ship.getPos()
vx, vy = ship.getVel()
```

Координаты и компоненты скорости возвращаются как `float`.

```python
ship.setName("Добытчик Альфа")
print(ship.getName())  # Добытчик Альфа
```

### Стыковка кораблей

Принимающий корабль вызывает `ship.readyToConnect()`, а второй —
`ship.connect(craft_id)`. Оба должны быть свободны, а расстояние между ними
не должно превышать **1**. Собственный ID, астероид и занятый корабль не подходят.
Стартовая верфь уже готова к стыковке.

`connect` и `disconnect` применяются на следующем тике мира и не возвращают
подтверждения; результат можно проверить через `getConnection()`.
После успешной стыковки готовность обоих кораблей сбрасывается в `False`.
Для следующей стыковки нужно снова вызвать `readyToConnect()`.

У пары совпадают координаты, угол, скорость и угловая скорость.
При стыковке скорости усредняются с учётом массы, а положение и угол
берутся у инициатора. Двигатели и RCS обоих кораблей действуют на общую массу;
команды гироскопов складываются. Энергия и топливные баки остаются у каждого
корабля своими. Расстыковку может вызвать любой участник;
оба сохранят скорость и угловую скорость пары. Связи сохраняются вместе с миром.

### Запуск скрипта на пристыкованном корабле

`ship.launch(path)` запускает Python-скрипт на текущем партнёре по стыковке.
Если на нём уже работает скрипт, он останавливается и заменяется новым.
Скрипт вызывающего корабля продолжает работать. Без пристыкованного корабля
команда ничего не делает.

Путь должен быть непустой строкой без NUL. Можно передать абсолютный путь
или путь относительно рабочего каталога игры. Рядом с запускаемым скриптом
должен быть доступен `api.py`, как при обычном запуске через интерфейс.

```python
if ship.getConnection()["connected"] is not None:
    ship.launch("worker.py")
    ship.disconnect()
```

`launch` выполняется на следующем тике мира без ожидания подтверждения.
Команды `connect`, `launch` и `disconnect` от одного скрипта выполняются
в порядке отправки: в примере сначала запускается скрипт партнёра,
затем корабли расстыковываются. Новый скрипт управляет кораблём, на котором
запущен, и получает его сохранённые данные событием `load_data`.


## Модули и характеристики

У добытчика установлены `propulsion_0`, `storage_0`, `rcs_0`, `drill_0`,
`scanner_0`, `power_0`, `fuel_tank_0`, `grab_0`. У верфи — `shipyard_0`, `factory_0`, склады
от `storage_0` до `storage_5` и источники питания от `power_0` до `power_9`.
Добытчик доставляет сырьё, верфь перерабатывает его и строит корабли и модули.

| Модуль | Имя | Характеристики по умолчанию |  Энергия |
| --- | --- | --- | --- |
| Основной двигатель | `propulsion_0` | Максимальная сила тяги **500**, тяга от **0 до 1**; расход топлива до **1 ед./с** | Не расходует |
| Склад | `storage_0` | Вместимость **20 единиц** | Не расходует |
| Маневровые двигатели и гироскоп | `rcs_0` | Сила тяги до **30**, угловая скорость до **100 / масса рад/с** | Не расходует |
| Бур | `drill_0` | **1 единица** ресурса за **0,5 с** работы с питанием, расстояние до астероида **≤ 10 м** | **10 ед./с**, пока включён и получает питание |
| Захват | `grab_0` | Один астероид в радиусе **10 м**, масса модуля **5** | Не расходует |
| Сканер | `scanner_0` | Радиус **500**, включая границу | **30 единиц за сканирование** |
| Источник питания | `power_0` | Ёмкость **100**, восстановление **5 ед./с** |  Восстанавливает заряд |
| Завод | `factory_0` | **1 рецепт за 3 с** работы с питанием | **20 ед./с** работы |
| Верфь | `shipyard_0` | **1 заказ за 3 с** работы с питанием |  **30 ед./с** работы |
| Топливный бак | `fuel_tank_0` | Вместимость **100**, одна единица `rocket_fuel` даёт **20 топлива** | Не расходует |

Имена установленных модулей узнавайте через `ship.getModules()`. Индекс после
подчёркивания начинается с 0 и считается отдельно для каждого типа модуля
на каждом корабле. Например: `storage_0`, `power_0`, `storage_1`.

На добытчике создайте объекты его модулей:

```python
prop = ship.Propulsion("propulsion_0")
storage = ship.Storage("storage_0")
rcs = ship.RCS("rcs_0")
power = ship.Power("power_0")
drill = ship.Drill("drill_0")
scanner = ship.Scanner("scanner_0")
grab = ship.Grab("grab_0")
```

На верфи используется другой набор модулей:

```python
yard = ship.Shipyard("shipyard_0")
factory = ship.Factory("factory_0")
storages = [ship.Storage(f"storage_{index}") for index in range(6)]
powers = [ship.Power(f"power_{index}") for index in range(10)]
```

Базовая масса корпуса — **10**. Масса добытчика с установленными модулями,
но без груза и топлива — **82**; со стартовыми 100 единицами топлива — **87**.
Масса верфи с её модулями и пустыми складами — **322**. Груз добавляет массу
своих ресурсов, захваченные астероиды — по **100** каждый;
число мест на складе и масса — разные величины.

### Основной двигатель — `Propulsion`

| Вызов | Действие |
| --- | --- |
| `prop.getMaxThrottle()` | Максимальная сила тяги; по умолчанию `500.0` |
| `prop.getFuelConsumption()` | Расход топлива в секунду при полной тяге; по умолчанию `10.0` |
| `prop.throttle(value=1.0)` | Установить долю тяги от 0 до 1 |

Ускорение направлено вперёд по кораблю и равно `500 × доля_тяги / масса`.

Двигатель расходует `1 × доля_тяги` единиц топлива в секунду.
На каждый шаг требуется запас в одном из баков своего корабля:
остатки из нескольких баков не суммируются. Если подходящего бака нет
или топлива на шаг не хватает, тяга обнуляется, ускорение не применяется.
После заправки тягу нужно задать снова.

`throttle(0)` выключает двигатель. Значения вне диапазона игнорируются.

```python
prop = ship.Propulsion("propulsion_0")
prop.throttle(0.3)
# Позже выключить ускорение:
prop.throttle(0)
```

Выключение двигателя не тормозит корабль и не останавливает его вращение.

### Маневровые двигатели и гироскоп — `RCS`

| Вызов | Действие |
| --- | --- |
| `rcs.getThrust()` | Максимальная сила маневровой тяги; по умолчанию `30.0` |
| `rcs.getMaxGyro()` | Коэффициент гироскопа; по умолчанию `100.0`; максимальная угловая скорость равна коэффициенту / массе |
| `rcs.setThrust(value=(0, 0))` | Задать вектор доли маневровой тяги `(x, y)` |
| `rcs.gyro(value=1.0)` | Задать долю угловой скорости от −1 до 1 |

Вектор тяги задан относительно корабля: X — вперёд, Y — влево.
Его направление поворачивается вместе с кораблём.

| Вектор | Направление тяги |
| --- | --- |
| `(1, 0)` | Вперёд |
| `(-1, 0)` | Назад |
| `(0, 1)` | Влево |
| `(0, -1)` | Вправо |
| `(0, 0)` | Выключить маневровую тягу |

Вектор длиной больше 1 сокращается до единичной длины с сохранением направления.
Для тяги нужны ровно два конечных числа; можно передать кортеж или список.

`gyro(1)` вращает корабль против часовой стрелки с максимальной угловой скоростью,
`gyro(-1)` — по часовой, `gyro(0)` останавливает вращение. Значения вне
диапазона от −1 до 1 игнорируются. Гироскоп задаёт скорость вращения, а не угол.
Для одного RCS угловая скорость равна `доля_гироскопа × 100 / масса` рад/с.
Если на корабле или состыкованной паре несколько RCS, их команды гироскопов
складываются, а в знаменателе используется общая масса.

```python
rcs = ship.RCS("rcs_0")
rcs.setThrust((-0.5, 0))
rcs.gyro(0.25)

# Позже остановить вращение и выключить маневровую тягу:
rcs.gyro(0)
rcs.setThrust((0, 0))
```

### Склад — `Storage`

Вместимость общая для всех ресурсов. Например, 12 единиц кремния и 8 единиц
железа полностью заполняют склад на 20 мест.

| Вызов | Действие / результат |
| --- | --- |
| `storage.getStorage()` | Содержимое в виде словаря, например `{"silicon": 3, "iron": 1}`; пустой склад — `{}` |
| `storage.transfer(resource)` | Передать одну единицу ресурса пристыкованному кораблю |

Все склады пристыкованного корабля автоматически доступны для передачи.
Отдельного разрешения на приём нет; ID в `transfer` больше не передаётся.

Передача выполняется, если одновременно соблюдены условия:

- У отправляющего склада есть хотя бы одна единица ресурса.
- Корабли состыкованы друг с другом.
- На получателе есть склад со свободным местом.

Если складов несколько, ресурс попадёт в первый подходящий. Передача
собственному кораблю и астероиду не выполняется. Если условия не соблюдены,
ресурс остаётся у отправителя. Результат команды не возвращается;
проверяйте содержимое склада через `getStorage()`.

На принимающей верфи:

```python
ship.readyToConnect()
```

На отправляющем добытчике, когда он находится в пределах 1 единицы от верфи:

```python
shipyard_id = 0
storage = ship.Storage("storage_0")
ship.connect(shipyard_id)
# В основном цикле, после подтверждения стыковки:
if ship.getConnection()["connected"] == shipyard_id:
    storage.transfer("silicon")
# После завершения всех передач:
ship.disconnect()
```

### Сканер — `Scanner`

```python
objects = ship.Scanner("scanner_0").scan()
```

Сканирование расходует **30 единиц энергии** и возвращает список всех объектов
на расстоянии **до 500 включительно**, включая собственный корабль.

Пример результата:

```python
[
    {"id": 0, "name": "Shipyard #0", "type": "craft", "x": 0.0, "y": 0.0},
    {"id": 10, "name": "Asteroid #10", "type": "asteroid", "x": 100.0, "y": 50.0},
]
```

| Поле | Значение |
| --- | --- |
| `id` | Числовой ID объекта, не зависит от имени |
| `name` | Текущее имя объекта из `Entity.GetName()` |
| `type` | `craft` — корабль, `asteroid` — астероид |
| `x` | Мировая координата X |
| `y` | Мировая координата Y |

Порядок объектов не фиксирован. Чтобы выбрать астероиды:

```python
asteroids = [obj for obj in objects if obj["type"] == "asteroid"]
```

Без достаточного заряда или источника питания результат — **`[]`**.

Сканер также может отправить текстовый сигнал кораблю по его ID:

```python
ship.Scanner("scanner_0").signal(0, "Груз доставлен")
```

`signal(craft_id, message)` принимает неотрицательный целый ID и строку.
Сигнал не расходует энергию и не ограничен радиусом сканирования.
Несуществующий ID и астероиды игнорируются; подтверждение не возвращается.

На получателе должен работать скрипт с обработчиком `signal`,
зарегистрированным до `ship.start()`. Сканер на получателе не требуется:

```python
@ship.on("signal")
def on_signal(data):
    print("Отправитель:", data["sender_id"], "Сообщение:", data["message"])
```

В `sender_id` передаётся ID отправляющего корабля, в `message` — текст.
Без обработчика событие игнорируется; сообщения не сохраняются до запуска скрипта.

### Бур — `Drill`

| Вызов | Действие / результат |
| --- | --- |
| `drill.getDrillCooldown()` | `0.5` — интервал добычи в секундах |
| `drill.enable()` | Включить бур |
| `drill.disable()` | Выключить бур |

Для добычи подлетите к центру астероида на расстояние **не больше 10 метров**
и удерживайте корабль рядом. Включённый бур добывает по одной случайной
оставшейся единице ресурса каждые 0,5 секунды работы с питанием. Добыча
попадает в первый склад корабля со свободным местом. Если рядом несколько
астероидов, конкретная цель по ID не задаётся.

Бур расходует **10 единиц энергии в секунду**.

Включённый бур расходует энергию и без астероида рядом. Отключайте его
при перелётах. Следите за свободным местом: в текущей версии добыча,
которая не поместилась в склад, теряется.


### Захват астероидов — `Grab`

Модуль устанавливается верфью через `yard.addModule(craft_id, "grab")`.
У нового стартового добытчика уже установлен `grab_0`.
На остальных кораблях после установки первого модуля им можно управлять
через `ship.Grab("grab_0")`.

| Вызов | Действие / результат |
| --- | --- |
| `grab.grab(asteroid_id)` | Захватить свободный астероид по ID на расстоянии **не больше 10** |
| `grab.release()` | Отпустить захваченный астероид |
| `grab.getGrabbed()` | ID удерживаемого астероида или `None`, если модуль свободен |
| `grab.getRadius()` | Радиус захвата: `10.0` |

Один модуль удерживает один астероид. Несколько модулей могут держать разные
астероиды; один астероид нельзя одновременно захватить двумя модулями.
Захват корабля, занятого астероида, несуществующей или слишком далёкой цели
ничего не меняет. Чтобы сменить астероид, сначала отпустите предыдущий.
Команды `grab` и `release` выполняются на следующем тике без подтверждения;
результат проверяйте через `getGrabbed()`.

Астероид сохраняет смещение относительно корабля и следует за его движением
и вращением. Его постоянная масса **100** прибавляется к массе корабля,
уменьшая ускорение и скорость вращения от гироскопов. При стыковке кораблей
учитываются астероиды обоих участников. Сам захват не расходует энергию
или топливо; работа двигателей остаётся обычной.

После отпускания астероид сохраняет текущие скорость и вращение,
включая скорость от вращения вокруг корабля. Его можно добывать буром,
пока он удерживается. Если астероид полностью добыт, связь очищается,
а его масса больше не учитывается. Уничтожение корабля освобождает астероид.
Захват и относительное положение сохраняются вместе с миром.

```python
grab = ship.Grab("grab_0")
grab.grab(asteroid_id)  # Цель найдена сканером, корабль уже в радиусе 10.
# После выполнения команды в основном цикле:
if grab.getGrabbed() == asteroid_id:
    print("Масса с астероидом:", ship.getMass())
# Для освобождения астероида:
grab.release()
```

| `power.getCapacity()` | Ёмкость источника; по умолчанию `100.0` |
| `power.getCharge()` | Текущий заряд |

Источник начинает работу с полным зарядом **100** и автоматически восстанавливает

### Топливный бак — `FuelTank`

tank = ship.FuelTank("fuel_tank_0")

### Завод — `Factory`

| Вызов | Действие / результат |
| --- | --- |
| `factory.getRecipes()` | Все рецепты в порядке их индексов, начиная с 0 |
| `factory.getQueue()` | Текущая очередь рецептов с `input` и `output` в порядке выполнения |
| `factory.produce(index)` | Добавить одно выполнение рецепта в конец очереди |

Имена `get_recipes` и `getRecipes` сохраняют написание из протокола.
Сейчас доступны **5 рецептов завода**; полный список — в [RECIPES.md](RECIPES.md).
Каждый рецепт содержит списки `input` и `output` с именами ресурсов.
Повтор имени означает ещё одну единицу: `["iron", "iron", "carbon"]` —
это 2 железа и 1 углерод. Например, первые три рецепта:

```python
[
    {"input": ["ice"], "output": ["water"]},
    {"input": ["water"], "output": ["hydrogen", "oxygen"]},
    {"input": ["iron", "iron", "carbon"], "output": ["steel"]},
    # Остальные рецепты доступны через getRecipes().
]
```

Завод выполняет заказы последовательно, по одному за **3 секунды работы с питанием**.
Сырьё собирается со всех складов своего корабля, продукция распределяется
по свободным местам. Учитываются и места, освобождаемые сырьём.
При нехватке сырья или места отсчёт приостанавливается, первый заказ
блокирует следующие. Заказ остаётся в очереди до успешного выполнения.

Во время производства завод расходует **20 единиц энергии в секунду**,
то есть **60 единиц за рецепт**. Энергия списывается за каждый шаг работы
из одного источника. Если заряда на шаг не хватает, прогресс приостанавливается
и продолжается с того же места после восстановления питания.
Сырьё списывается одновременно с размещением всей продукции в конце рецепта;
при ожидании ресурсы остаются на складах, заряд не расходуется.
Очередь сохраняется при завершении или замене управляющего скрипта.

```python
factory = ship.Factory("factory_0")
recipes = factory.getRecipes()
for index, recipe in enumerate(recipes):
    print(index, recipe["input"], "->", recipe["output"])

# При наличии льда: сначала вода, затем водород и кислород.
water_recipie = 0
h2_o2_recipie = 1
factory.produce(water_recipie)
factory.produce(h2_o2_recipie)
print(factory.getQueue())
# Команды не ждут завершения; результат проверяйте в складе.
```

`getQueue()` отправляет запрос `get_queue` и возвращает снимок очереди.
Формат каждого элемента совпадает с рецептом из `getRecipes()`:
`{"input": ["ice"], "output": ["water"]}`. Первый элемент — текущий
незавершённый заказ, в том числе ожидающий ресурсов, места или питания.
Повторные заказы остаются отдельными элементами. Пустая очередь — `[]`.
Чтение очереди не изменяет её; завершённые заказы в ответ не входят.

`produce` передаёт неотрицательный целый индекс в поле `value`.
Выход за границы списка отклоняется сервером и не меняет очередь;
как у других команд, ошибка видна в консоли без отдельного ответа.


### Верфь — `Shipyard`

```python
yard = ship.Shipyard("shipyard_0")
print(yard.getRecipes())
yard.addModule(ship.getId(), "storage")  # Установить склад на свой корабль.
yard.constructCraft()                   # Построить пустой корабль и пристыковать к верфи.
```

| Вызов | Действие / результат |
| --- | --- |
| `yard.getRecipes()` | Список рецептов: `input` — имена ресурсов, `output` — `craft` или имя типа модуля |
| `yard.getQueue()` | Текущая очередь заказов с `output` и `craft_id` в порядке выполнения |
| `yard.constructCraft()` | Поставить в очередь строительство пустого корабля с автоматической стыковкой к верфи |
| `yard.addModule(craft_id, module_name)` | Поставить установку модуля на указанный корабль в очередь |

`getQueue()` отправляет запрос `get_queue`. Ответ — снимок очереди,
начиная с текущего незавершённого заказа, включая ожидающие заказы.
`output` содержит `craft` или имя типа модуля, а `craft_id` — ID корабля,
на который устанавливается модуль. Для строительства нового корабля
`craft_id` равен `None` (в JSON — `null`): ID назначается при создании.
Например:

```python
[
    {"output": "storage", "craft_id": 0},
    {"output": "craft", "craft_id": None},
]
```

Пустая очередь — `[]`. Чтение не изменяет очередь; завершённые
и пропущенные заказы в ответ не входят.

Типы модулей: `propulsion`, `storage`, `rcs`, `drill`, `scanner`, `power`,
`factory`, `shipyard`, `fuel_tank`, `grab`. Передаётся имя типа без числового суффикса.
Пустой корабль и каждый модуль требуют по **1 единице `steel`**.
Цель установки должна находиться на расстоянии **не больше 20** от верфи.
При выходе из радиуса, нехватке сырья или энергии заказ ждёт с сохранением
прогресса. Отсутствующий корабль пропускается с сообщением в консоли.
Каждый заказ занимает **3 секунды работы с питанием**, расход — **30 ед./с**.
Сырьё списывается в момент завершения со складов корабля с верфью.

Для строительства нового корабля стыковочный узел верфи должен быть свободен.
Если к ней уже пристыкован любой корабль, строительство приостанавливается:
прогресс сохраняется, энергия и ресурсы не расходуются. Заказ остаётся первым
в очереди и блокирует следующие до расстыковки. Установка модулей может
выполняться при занятом узле, если её заказ находится первым в очереди.

Обе строительные команды отправляются без ожидания подтверждения.
Установку на свой корабль можно проверить через `getModules()`, создание
корабля — через `ship.getConnection()["connected"]`: после сборки здесь
будет ID нового корабля. Он появляется в координатах верфи, наследует её
скорость, угол и угловую скорость и сразу взаимно стыкуется с ней.
Для этой автоматической стыковки флаг `readyToConnect` не требуется;
готовность обоих кораблей сбрасывается в `False`. Модули устанавливаются отдельно.
Пока новый корабль остаётся пристыкованным, следующий корпус не строится.
На него можно установить модули через `yard.addModule(id, module_name)`
и запустить скрипт через `ship.launch(path)`, затем вызвать `ship.disconnect()`
для освобождения узла верфи.
Он получает имя `Craft #ID`, которое затем можно изменить скриптом,
запущенным на этом корабле. Полное выполнение одного строительного заказа
расходует **90 единиц энергии**.


## Сохранение и загрузка мира

В главном меню укажите путь к файлу и выберите «Сохранить игру»
или «Загрузить игру». Мир записывается в JSON. Сохраняются:

- ID, имена, координаты, скорости, углы и угловые скорости объектов.
- Ресурсы астероидов, установленные модули, груз, топливо и заряд.
- Настройки модулей, очереди и прогресс завода и верфи.
- Стыковка кораблей и их готовность к стыковке.
- Захваченные астероиды, их смещение и относительный угол.
- Пути управляющих скриптов и строки, записанные через `ship.saveData()`.

При загрузке сначала восстанавливаются объекты, стыковки и захваты,
затем запускаются скрипты. Масса вычисляется из восстановленного состояния,
включая груз, топливо и захваченные астероиды. Старые файлы без полей
стыковки загружаются с несостыкованными кораблями.

Ещё не выполненные команды API в файл не попадают, в отличие от очередей
производства завода и верфи. Перед сохранением проверьте результат важных
команд через API. В меню мир не обновляется, поэтому команды, ожидающие
следующего тика, выполнятся после возвращения в игру. Ошибки чтения
или записи выводятся в консоль игры; при ошибке загрузки текущий мир сохраняется.

## Сохранение состояния скрипта

`ship.saveData(data)` отправляет команду `save_data` с полем `value` — строкой.
Корабль записывает её в `Craft.script_data`, заменяя предыдущее значение.
Можно передать пустую строку `""`, чтобы очистить состояние. Другие типы
Python API отклоняет с `ValueError`; словари и списки предварительно
преобразуйте в строку, например через `json.dumps()`.

Команда отправляется без ожидания подтверждения. Она обновляет данные
в памяти: для записи на диск сохраните мир через «Сохранить игру» в главном
меню. В файл каждого корабля попадают его `script_data` и путь к скрипту.
При загрузке мира скрипты с сохранёнными путями автоматически запускаются заново.

При каждом запуске, включая ручной перезапуск, скрипт получает событие
`load_data`. Обработчику передаётся сама сохранённая строка, без словаря-обёртки.
У нового корабля и в старых сохранениях без `script_data` это `""`.
Зарегистрируйте обработчик **до `ship.start()`**, иначе событие можно пропустить.
Данные сохраняются при завершении или замене скрипта и принадлежат кораблю.

```python
import json
import threading
import time
import api as ship

state = {"stage": "mining", "target_id": None}
restored = threading.Event()

@ship.on("load_data")
def on_load_data(data):
    if data:
        state.update(json.loads(data))
    restored.set()

ship.start()
if not restored.wait(timeout=2.0):
    raise RuntimeError("Не получено начальное состояние скрипта")

print("Продолжаем этап:", state["stage"])
state["stage"] = "returning"
ship.saveData(json.dumps(state, ensure_ascii=False))

while ship.is_running():
    time.sleep(0.1)
```

Сохраняйте состояние после важных изменений: переменные Python сами по себе
не попадают в файл мира. `load_data` восстанавливает последнюю строку из
`saveData()`, а выполнение Python начинается с начала файла скрипта.

## События консоли

Зарегистрируйте обработчик до `ship.start()`. Он будет получать строки,
которые игрок отправляет выбранному кораблю через консоль.

```python
import time
import api as ship

@ship.on("console_message")
def on_message(message):
    if message == "inventory":
        print(ship.Storage("storage_0").getStorage())
    elif message == "stop":
        ship.Propulsion("propulsion_0").throttle(0)
        rcs = ship.RCS("rcs_0")
        rcs.gyro(0)
        rcs.setThrust((0, 0))
        ship.command("disable", module="drill_0")

ship.start()
while ship.is_running():
    time.sleep(0.1)
```

Для одного имени события действует один обработчик. Автоматических событий
обнаружения астероида и получения ресурса сейчас нет: используйте сканирование
и чтение инвентаря.

## Ошибки и завершение скрипта

- `TimeoutError` — ответ не получен за заданное время. Проверьте имя модуля
  и имя запроса. Запрос к отсутствующему модулю также заканчивается тайм-аутом.
- `RuntimeError` — соединение закрыто, получен ответ с ошибкой или повторно
  вызван `start()`.
- `ValueError` — Python API отклонил пустое имя корабля, нестроковые данные
  `saveData()`, неверный индекс рецепта
  или неверные параметры `Shipyard.addModule()` / `Scanner.signal()`,
  `connect()`, `readyToConnect()`, `launch()`, `Storage.transfer()` / `Grab.grab()`.
  Индекс за пределами списка рецептов проверяет бэкенд: сообщение появится в консоли.
- Команда к отсутствующему модулю пропускается. Для неверных параметров команды
  сообщение об ошибке может появиться только в консоли.

Тяга, команды гироскопов, состояние бура, стыковка и захваты сохраняются
после завершения скрипта. Основная тяга сбрасывается при нехватке топлива;
готовность к стыковке — после успешной стыковки. Чтобы выключить
оборудование при обычном выходе из скрипта, используйте `finally`:

```python
import time
import api as ship

ship.start()
prop = ship.Propulsion("propulsion_0")
rcs = ship.RCS("rcs_0")

try:
    prop.throttle(0.2)
    while ship.is_running():
        time.sleep(0.1)
finally:
    if ship.is_running():
        prop.throttle(0)
        rcs.gyro(0)
        rcs.setThrust((0, 0))
        ship.command("disable", module="drill_0")
```

Этот пример выключает ускорение и вращение; уже набранная линейная скорость
сохраняется. Новому скрипту следует явно задавать нужные состояния модулей.
