# Project Asteroid — справочник игрока

Управляйте кораблями через Python: исследуйте пространство, добывайте ресурсы,
перерабатывайте их на заводе и стройте новые корабли на верфи. Этот справочник
описывает запуск игры, правила мира, оборудование и текущий Python API.

## Мир и координаты

В начальном мире находятся два корабля и 50 астероидов:

- **Shipyard #0** в `(0, 0)` — тяжёлая верфь без двигателей: модуль верфи,
  завод, 6 складов общей вместимостью 120 единиц и 10 источников питания.
  Склады сразу готовы принимать ресурсы. Масса без груза — 312.
- **Miner #1** в `(30, 0)` — добытчик с основным двигателем, маневровыми
  двигателями, складом, буром, сканером и источником питания. Масса без груза — 62.

Оба корабля первоначально неподвижны, склады пусты. Астероиды неподвижны
и появляются в случайных точках с координатами X и Y от −1000 до 1000.

Каждый объект имеет числовой ID. В начальном мире ID кораблей — 0 и 1,
астероидов — от 2 до 51. Имена задаются при создании: `Shipyard #0`,
`Miner #1`, `Asteroid #2` и так далее. Интерфейс и сканер используют имя,
хранящееся в `Entity`. Корабль можно переименовать через `ship.setName()`;
числовой ID и тип объекта при этом сохраняются.

| Величина | Значение |
| --- | --- |
| Ось X | Вправо |
| Ось Y | Вверх |
| Расстояние | Единицы мира |
| Скорость | Единицы мира в секунду |
| Ускорение | Единицы мира в секунду² |
| Угол | Радианы: 0 — вправо, π/2 — вверх |
| Положительное вращение | Против часовой стрелки |
| Угловая скорость | Радианы в секунду |

Трения нет: выключение двигателя прекращает ускорение, но сохраняет скорость.
Для остановки нужна тяга против направления движения. Ускорения основного
двигателя и маневровых двигателей складываются.

### Ресурсы

В каждом астероиде находится суммарно от **1 до 10 единиц** случайных ресурсов.
После извлечения последней единицы астероид исчезает. Одна единица любого
ресурса занимает одно место в складе.

| Ресурс | Имя для API |
| --- | --- |
| Кремний | `silicon` |
| Углерод | `carbon` |
| Железо | `iron` |
| Лёд | `ice` |
| Медь | `copper` |
| Золото | `gold` |

Сырьё из таблицы добывается на астероидах. Остальные материалы и изделия
создаются заводом: вода, газы, сталь, провода, электроника и готовые изделия.
Полный список преобразований возвращает `Factory.getRecipies()`.
Готовые изделия хранятся как ресурсы и не устанавливают модули на корабль.

## Запуск скрипта и консоль

Выберите корабль в списке слева или нажмите на него в мире. В поле пути
к скрипту введите путь к вашему файлу, например `scripts/miner.py` для добытчика,
и нажмите Enter. Скрипт управляет выбранным кораблём. Повторный запуск
заменяет его предыдущий скрипт.

Камера следует за выбранным объектом. Без выбранного объекта клавиши WASD
перемещают камеру, если поле ввода не активно. Escape снимает фокус ввода;
вне активной консоли также сбрасывает выбор объекта.

`print()` выводит сообщения в нижнюю игровую консоль. Колесо мыши над ней
прокручивает вывод. Хранятся последние 1000 строк, старые вытесняются новыми.

Для отправки сообщения скрипту нажмите на консоль, введите текст и нажмите
Enter. Скрипт получит событие `console_message`. Стрелки ↑/↓ перебирают
историю сообщений. В полях ввода работают стрелки, Home/End, Backspace/Delete
и Ctrl/Cmd+V.


## Начало работы с API

В начале скрипта импортируйте [`api`](scripts/api.py) и один раз вызовите `start()`.
`is_running()` сообщает, остаётся ли соединение с кораблём активным.
Пример ниже предназначен для добытчика:

```python
import time
import api as ship

ship.start()

print("Корабль:", ship.getId())
print("Имя:", ship.getName())
print("Координаты:", ship.getPos())
print("Модули:", ship.getModules())

storage = ship.Storage("storage_1")
power = ship.Power("power_5")
print("Инвентарь:", storage.getStorage())
print("Заряд:", power.getCharge())

while ship.is_running():
    time.sleep(0.1)
```

Все объекты модулей обращаются к кораблю, для которого запущен скрипт.
Передача ресурсов и установка модуля верфью дополнительно принимают ID
корабля-цели. Переименование меняет имя только своего корабля.

### Состояние корабля

| Вызов | Результат |
| --- | --- |
| `ship.start()` | Запускает соединение с кораблём; вызывается один раз |
| `ship.is_running()` | `True`, пока соединение активно |
| `ship.getId(timeout=2.0)` | ID корабля: `int` |
| `ship.getName(timeout=2.0)` | Текущее имя корабля |
| `ship.setName(name)` | Переименовать свой корабль; непустая строка |
| `ship.getPos(timeout=2.0)` | Мировые координаты `(x, y)` |
| `ship.getVel(timeout=2.0)` | Мировая скорость `(vx, vy)` |
| `ship.getAngle(timeout=2.0)` | Угол корабля: `float`, радианы |
| `ship.getAngularVelocity(timeout=2.0)` | Угловая скорость: `float`, рад/с |
| `ship.getModules(timeout=2.0)` | Список имён установленных модулей |
| `ship.getMass(timeout=2.0)` | Масса корабля с грузом |

```python
x, y = ship.getPos()
vx, vy = ship.getVel()
```

Координаты и компоненты скорости возвращаются как `float`.
`timeout` задаёт максимальное время ожидания ответа в секундах.

```python
ship.setName("Добытчик Альфа")
print(ship.getName())  # Добытчик Альфа
```

`setName()` — команда без ожидания подтверждения. Новое имя отображается
в списке объектов, панели выбранного корабля, заголовке консоли и сканировании.
Имена не обязаны быть уникальными; для обращения к кораблю используйте его ID.

## Модули и характеристики

У добытчика установлены `propulsion_0`, `storage_1`, `rcs_2`, `drill_3`,
`scaner_4`, `power_5`. У верфи — `shipyard_0`, `factory_1`, склады
от `storage_2` до `storage_7` и источники питания от `power_8` до `power_17`.
Добытчик доставляет сырьё, верфь перерабатывает его и строит корабли и модули.

| Модуль | Имя | Характеристики по умолчанию | Начальное состояние модуля | Энергия |
| --- | --- | --- | --- | --- |
| Основной двигатель | `propulsion_0` | Максимальная сила тяги **100**, тяга от **0 до 1** | Тяга **0** | Не расходует |
| Склад | `storage_1` | Вместимость **20 единиц**, передача **1 единицы** за команду на расстояние **≤ 10** | Пустой; на верфи приём включён | Не расходует |
| Маневровые двигатели и гироскоп | `rcs_2` | Сила тяги до **10**, угловая скорость до **1 рад/с** | Тяга **(0, 0)**, вращение **0** | Не расходует |
| Бур | `drill_3` | **1 единица** ресурса за **0,5 с** работы с питанием, расстояние до астероида **< 1** | Выключен | **5 ед./с**, пока включён и получает питание |
| Сканер | `scaner_4` | Радиус **500**, включая границу | Работает по запросу | **30 единиц за сканирование** |
| Источник питания | `power_5` | Ёмкость **100**, восстановление **5 ед./с** | Заряд **100** | Восстанавливает заряд |
| Завод | `factory_1` | **1 рецепт за 3 с** работы с питанием, очередь FIFO | Очередь пуста | **20 ед./с** работы |
| Верфь | `shipyard_0` | **1 заказ за 3 с** работы с питанием, радиус установки модулей **20** | Очередь пуста | **30 ед./с** работы |

Имена установленных модулей узнавайте через `ship.getModules()`. Число после
подчёркивания зависит от порядка установки, а не от вида модуля.

На добытчике создайте объекты его модулей:

```python
prop = ship.Propulsion("propulsion_0")
storage = ship.Storage("storage_1")
rcs = ship.RCS("rcs_2")
power = ship.Power("power_5")
drill = ship.Drill("drill_3")
scaner = ship.Scaner("scaner_4")
```

На верфи используется другой набор имён:

```python
yard = ship.Shipyard("shipyard_0")
factory = ship.Factory("factory_1")
storages = [ship.Storage(f"storage_{index}") for index in range(2, 8)]
powers = [ship.Power(f"power_{index}") for index in range(8, 18)]
```

Масса пустого добытчика — **62**, верфи — **312**. Груз добавляет массу
своих ресурсов; число мест на складе и масса — разные величины.
Линейное ускорение равно силе тяги, делённой на текущую массу корабля.
При изменении груза масса пересчитывается перед следующим обновлением модулей.

### Основной двигатель — `Propulsion`

| Вызов | Действие |
| --- | --- |
| `prop.getMaxThrottle(timeout=2.0)` | Максимальная сила тяги; по умолчанию `100.0` |
| `prop.throttle(value=1.0)` | Установить долю тяги от 0 до 1 |

Ускорение направлено вперёд по кораблю и равно `100 × доля_тяги / масса`.
Для пустого добытчика `throttle(0.3)` даёт примерно 0,484 ед./с²,
`throttle(0)` выключает двигатель. Значения вне диапазона игнорируются.

```python
prop = ship.Propulsion("propulsion_0")
prop.throttle(0.3)
# Позже выключить ускорение:
prop.throttle(0)
```

Выключение двигателя не тормозит корабль и не останавливает его вращение.

### Маневровые двигатели и гироскоп — `RCS`

| Вызов | Действие |
| --- | --- |
| `rcs.getThrust(timeout=2.0)` | Максимальная сила маневровой тяги; по умолчанию `10.0` |
| `rcs.getMaxGyro(timeout=2.0)` | Максимальная угловая скорость; по умолчанию `1.0` рад/с |
| `rcs.setThrust(value=(0, 0))` | Задать вектор доли маневровой тяги `(x, y)` |
| `rcs.gyro(value=1.0)` | Задать долю угловой скорости от −1 до 1 |

Вектор тяги задан относительно корабля: X — вперёд, Y — влево.
Его направление поворачивается вместе с кораблём.

| Вектор | Направление тяги |
| --- | --- |
| `(1, 0)` | Вперёд |
| `(-1, 0)` | Назад |
| `(0, 1)` | Влево |
| `(0, -1)` | Вправо |
| `(0, 0)` | Выключить маневровую тягу |

Вектор длиной больше 1 сокращается до единичной длины с сохранением направления.
Для тяги нужны ровно два конечных числа; можно передать кортеж или список.

`gyro(1)` вращает корабль против часовой стрелки с максимальной угловой скоростью,
`gyro(-1)` — по часовой, `gyro(0)` останавливает вращение. Значения вне
диапазона от −1 до 1 игнорируются. Гироскоп задаёт скорость вращения, а не угол.

```python
rcs = ship.RCS("rcs_2")
rcs.setThrust((-0.5, 0))
rcs.gyro(0.25)

# Позже остановить вращение и выключить маневровую тягу:
rcs.gyro(0)
rcs.setThrust((0, 0))
```

### Склад — `Storage`

Вместимость общая для всех ресурсов. Например, 12 единиц кремния и 8 единиц
железа полностью заполняют склад на 20 мест.

| Вызов | Действие / результат |
| --- | --- |
| `storage.getStorage(timeout=2.0)` | Содержимое в виде словаря, например `{"silicon": 3, "iron": 1}`; пустой склад — `{}` |
| `storage.readyForRecieve()` | Разрешить принимать ресурсы от других кораблей |
| `storage.notReadyForRecieve()` | Запретить приём от других кораблей |
| `storage.transfer(id, resource)` | Передать одну единицу указанного ресурса кораблю с ID `id` |

У нового склада приём по умолчанию отключён; у стартовой верфи он уже включён.
Разрешение относится к конкретному складу
и сохраняется, пока его не отключат. На отправку ресурсов это разрешение
не влияет. `getStorage()` ожидает ответ до 2 секунд.

Передача выполняется, если одновременно соблюдены условия:

- У отправляющего склада есть хотя бы одна единица ресурса.
- Получатель — другой корабль на расстоянии **не больше 10**.
- На получателе есть склад с разрешённым приёмом и свободным местом.

Если складов несколько, ресурс попадёт в первый подходящий. Передача
собственному кораблю и астероиду не выполняется. Если условия не соблюдены,
ресурс остаётся у отправителя. Результат команды не возвращается;
проверяйте содержимое склада через `getStorage()`.

На принимающей верфи, например для первого склада:

```python
storage = ship.Storage("storage_2")
storage.readyForRecieve()
```

На отправляющем добытчике, когда он находится в пределах 10 единиц от верфи:

```python
storage = ship.Storage("storage_1")
storage.transfer(0, "silicon")  # Одна единица кремния верфи с ID 0.
```

Чтобы прекратить приём на получателе:

```python
storage.notReadyForRecieve()
```

### Сканер — `Scaner`

```python
objects = ship.Scaner("scaner_4").scan(timeout=2.0)
```

Сканирование расходует **30 единиц энергии** и возвращает список всех объектов
на расстоянии **до 500 включительно**, включая собственный корабль.

Пример результата:

```python
[
    {"id": 0, "name": "Shipyard #0", "type": "craft", "x": 0.0, "y": 0.0},
    {"id": 10, "name": "Asteroid #10", "type": "asteroid", "x": 100.0, "y": 50.0},
]
```

| Поле | Значение |
| --- | --- |
| `id` | Числовой ID объекта, не зависит от имени |
| `name` | Текущее имя объекта из `Entity.GetName()` |
| `type` | `craft` — корабль, `asteroid` — астероид |
| `x` | Мировая координата X |
| `y` | Мировая координата Y |

Порядок объектов не фиксирован. Чтобы выбрать астероиды:

```python
asteroids = [obj for obj in objects if obj["type"] == "asteroid"]
```

Без достаточного заряда или источника питания результат — **`[]`**.
Такой ответ не означает, что ранее обнаруженный астероид исчез: сначала
проверьте заряд и дождитесь его восстановления. Автоматического сканирования нет.

### Бур — `Drill`

| Вызов | Действие / результат |
| --- | --- |
| `drill.getDrillCooldown(timeout=2.0)` | `0.5` — интервал добычи в секундах |
| `drill.enable()` | Включить бур |
| `drill.disable()` | Выключить бур |

Для добычи подлетите к центру астероида на расстояние **строго меньше 1**
и удерживайте корабль рядом. Включённый бур добывает по одной случайной
оставшейся единице ресурса каждые 0,5 секунды работы с питанием. Добыча
попадает в первый склад корабля со свободным местом. Если рядом несколько
астероидов, конкретная цель по ID не задаётся.

Бур расходует **5 единиц энергии в секунду**. Без питания накопление времени
до следующей добычи приостанавливается и продолжается после восстановления
заряда. При выключении бура накопленное время сбрасывается.

Включённый бур расходует энергию и без астероида рядом. Отключайте его
при перелётах. Следите за свободным местом: в текущей версии добыча,
которая не поместилась в склад, теряется.

```python
ship.command("enable", module="drill_3")
# Во время бурения проверяйте инвентарь:
print(ship.Storage("storage_1").getStorage())
# Когда добыча больше не нужна:
ship.command("disable", module="drill_3")
```

### Источник питания — `Power`

| Вызов | Результат |
| --- | --- |
| `power.getCapacity(timeout=2.0)` | Ёмкость источника; по умолчанию `100.0` |
| `power.getCharge(timeout=2.0)` | Текущий заряд |

Источник начинает работу с полным зарядом **100** и автоматически восстанавливает
**5 единиц в секунду**, пока не заполнится. Отдельная команда включения не нужна.

Сканер, бур, завод и верфь используют энергию источников на своём корабле. Если источников
несколько, выбирается первый с достаточным зарядом для операции. Заряды разных
источников для одной операции не складываются.

Без других потребителей один источник восстанавливает стоимость одного
сканирования за **6 секунд**. Сканирование каждые 0,5 секунды требует примерно
60 ед./с, поэтому быстро разряжает источник. Включённый бур потребляет столько же
энергии в секунду, сколько восстанавливает один стандартный источник;
дополнительные сканирования расходуют запас заряда.

```python
power = ship.Power("power_5")
if power.getCharge() >= 30:
    objects = ship.Scaner("scaner_4").scan()
    print(objects)
```

### Завод — `Factory`

| Вызов | Действие / результат |
| --- | --- |
| `factory.getRecipies(timeout=2.0)` | Все рецепты в порядке их индексов, начиная с 0 |
| `factory.produce(index)` | Добавить одно выполнение рецепта в конец очереди |

Имена `get_recipies` и `getRecipies` сохраняют написание из протокола.
Каждый рецепт содержит списки `input` и `output` с именами ресурсов.
Повтор имени означает ещё одну единицу: `["iron", "iron", "carbon"]` —
это 2 железа и 1 углерод. Например, первые три рецепта:

```python
[
    {"input": ["ice"], "output": ["water"]},
    {"input": ["water"], "output": ["hydrogen", "oxygen"]},
    {"input": ["iron", "iron", "carbon"], "output": ["steel"]},
    # Остальные рецепты доступны через getRecipies().
]
```

Завод выполняет заказы последовательно, по одному за **3 секунды работы с питанием**.
Сырьё собирается со всех складов своего корабля, продукция распределяется
по свободным местам. Учитываются и места, освобождаемые сырьём.
При нехватке сырья или места отсчёт приостанавливается, первый заказ
блокирует следующие. Заказ остаётся в очереди до успешного выполнения.

Во время производства завод расходует **20 единиц энергии в секунду**,
то есть **60 единиц за рецепт**. Энергия списывается за каждый шаг работы
из одного источника. Если заряда на шаг не хватает, прогресс приостанавливается
и продолжается с того же места после восстановления питания.
Сырьё списывается одновременно с размещением всей продукции в конце рецепта;
при ожидании ресурсы остаются на складах, заряд не расходуется.
Очередь сохраняется при завершении или замене управляющего скрипта.

```python
factory = ship.Factory("factory_1")
recipies = factory.getRecipies()
for index, recipie in enumerate(recipies):
    print(index, recipie["input"], "->", recipie["output"])

# При наличии льда: сначала вода, затем водород и кислород.
factory.produce(0)
factory.produce(1)
# Команды не ждут завершения; результат проверяйте в складе.
```

`produce` передаёт неотрицательный целый индекс в поле `value`.
Выход за границы списка отклоняется сервером и не меняет очередь;
как у других команд, ошибка видна в консоли без отдельного ответа.

Пример обмена JSON (каждый пакет — отдельная строка):

```json
{"type":"request","id":1,"module":"factory_1","method":"get_recipies"}
{"type":"response","id":1,"result":[{"input":["ice"],"output":["water"]}]}
{"type":"command","module":"factory_1","method":"produce","value":0}
```

Ответ выше сокращён до первого рецепта; реальный ответ содержит весь список.

### Верфь — `Shipyard`

```python
yard = ship.Shipyard("shipyard_0")
print(yard.getRecipies())
yard.addModule(ship.getId(), "storage")  # Установить склад на свой корабль.
yard.constructCraft()                   # Построить пустой корабль.
```

| Вызов | Действие / результат |
| --- | --- |
| `yard.getRecipies(timeout=2.0)` | Список рецептов: `input` — имена ресурсов, `output` — `craft` или имя типа модуля |
| `yard.constructCraft()` | Поставить строительство пустого корабля в очередь |
| `yard.addModule(craft_id, module_name)` | Поставить установку модуля на указанный корабль в очередь |

Типы модулей: `propulsion`, `storage`, `rcs`, `drill`, `scaner`, `power`,
`factory`, `shipyard`. Передаётся имя типа без числового суффикса.
Цель установки должна находиться на расстоянии **не больше 20** от верфи.
При выходе из радиуса, нехватке сырья или энергии заказ ждёт с сохранением
прогресса. Отсутствующий корабль пропускается с сообщением в консоли.
Каждый заказ занимает **3 секунды работы с питанием**, расход — **30 ед./с**.
Сырьё списывается в момент завершения со складов корабля с верфью.

Текущие строительные рецепты:

| Результат | Ресурсы |
| --- | --- |
| Пустой корабль (`craft`) | 2 × `iron_plate`, 1 × `circuit_board` |
| `propulsion` | 1 × `iron_plate`, 2 × `pipe`, 1 × `circuit_board` |
| `storage` | 2 × `iron_plate` |
| `rcs` | 1 × `iron_plate`, 1 × `pipe`, 1 × `copper_wire` |
| `drill` | 1 × `iron_plate`, 1 × `gear`, 1 × `electric_motor` |
| `scaner` | 1 × `silicon_wafer`, 1 × `copper_wire`, 1 × `glass` |
| `power` | 1 × `solar_cell`, 1 × `battery_cell`, 1 × `copper_wire` |
| `factory` | 1 × `iron_plate`, 1 × `gear`, 1 × `electric_motor`, 1 × `circuit_board` |
| `shipyard` | 2 × `iron_plate`, 1 × `electric_motor`, 1 × `circuit_board` |

Обе строительные команды отправляются без ожидания подтверждения.
Бэкенд пока не возвращает ID построенного корабля и состояние очередей.
Установку на свой корабль можно проверить через `getModules()`, создание
корабля — в мире или сканером. Новый корабль появляется в 10 единицах
впереди верфи и наследует её скорость и угол; модули устанавливаются отдельно.
Он получает имя `Craft #ID`, которое затем можно изменить скриптом,
запущенным на этом корабле. Полное выполнение одного строительного заказа
расходует **90 единиц энергии**.

## Общие запросы и команды

Для методов без отдельной обёртки используйте:

```python
result = ship._request(method, module="имя_модуля", timeout=2.0)
ship.command(method, module="имя_модуля", **params)
```

Запрос возвращает результат. Команда отправляет действие без ожидания
подтверждения. Все методы `throttle`, `gyro`, `setThrust`, переключение приёма,
передача ресурсов, переименование через `setName()`, включение/выключение бура, `factory.produce()`,
`yard.constructCraft()` и `yard.addModule()` являются командами.

Запросы корабля используют `module="none"`:

| Метод | `result` |
| --- | --- |
| `get_id` | `{"craft_id": число}` |
| `get_name` | `{"name": строка}` |
| `get_position` | `{"x": число, "y": число}` |
| `get_velocity` | `{"x": число, "y": число}` |
| `get_angle` | `{"angle": число}` |
| `get_angular_velocity` | `{"angular_velocity": число}` |
| `get_modules` | `{"modules": [имена модулей]}` |
| `get_mass` | `{"mass": число}` |

Переименование отправляется командой `set_name` с `value="Новое имя"`:

```python
ship.command("set_name", value="Добытчик Альфа")
```

Имена методов и параметры для прямого обращения к модулям:

| Модуль | Запросы | Команды и параметры |
| --- | --- | --- |
| `propulsion_0` | `get_max_throttle` → `{"max_throttle": число}` | `set_throttle`, `value=доля_тяги` |
| `storage_1` | `get_storage` → список `{"resource": имя, "count": количество}` | `ready_for_recieve`; `not_ready_for_recieve`; `transfer`, `value=[id, "имя_ресурса"]` |
| `rcs_2` | `get_max_gyro` → `{"max_gyro": число}`; `get_max_thrust` → `{"max_thrust": число}` | `set_gyro`, `value=доля_вращения`; `set_thrust`, `value=[x, y]` |
| `drill_3` | `get_drill_cooldown` → `{"drill_cooldown": секунды}` | `enable`; `disable` |
| `scaner_4` | `scan` → список обнаруженных объектов | — |
| `power_5` | `get_capacity` → `{"capacity": число}`; `get_charge` → `{"charge": число}` | — |
| `factory_1` | `get_recipies` → список `{"input": [имена ресурсов], "output": [имена ресурсов]}` | `produce`, `value=индекс_рецепта` |
| `shipyard_0` | `get_recipies` → список `{"input": [имена ресурсов], "output": тип_модуля_или_craft}` | `construct_craft`; `add_module`, `value=[craft_id, "тип_модуля"]` |

Например, эти команды эквивалентны:

```python
ship.Propulsion("propulsion_0").throttle(0.5)
ship.command("set_throttle", module="propulsion_0", value=0.5)
```

## События консоли

Зарегистрируйте обработчик до `ship.start()`. Он будет получать строки,
которые игрок отправляет выбранному кораблю через консоль.

```python
import time
import api as ship

@ship.on("console_message")
def on_message(message):
    if message == "inventory":
        print(ship.Storage("storage_1").getStorage())
    elif message == "stop":
        ship.Propulsion("propulsion_0").throttle(0)
        rcs = ship.RCS("rcs_2")
        rcs.gyro(0)
        rcs.setThrust((0, 0))
        ship.command("disable", module="drill_3")

ship.start()
while ship.is_running():
    time.sleep(0.1)
```

Для одного имени события действует один обработчик. Автоматических событий
обнаружения астероида и получения ресурса сейчас нет: используйте сканирование
и чтение инвентаря.

## Ошибки и завершение скрипта

- `TimeoutError` — ответ не получен за заданное время. Проверьте имя модуля
  и имя запроса. Запрос к отсутствующему модулю также заканчивается тайм-аутом.
- `RuntimeError` — соединение закрыто, получен ответ с ошибкой или повторно
  вызван `start()`.
- `ValueError` — Python API отклонил пустое имя корабля, неверный индекс рецепта
  или неверные параметры `Shipyard.addModule()`. Индекс за пределами списка
  рецептов проверяет бэкенд: сообщение появится в консоли.
- Команда к отсутствующему модулю пропускается. Для неверных параметров команды
  сообщение об ошибке может появиться только в консоли.

Тяга, вращение, состояние бура и разрешение приёма сохраняются до следующей
команды. Завершение скрипта само по себе их не сбрасывает. Чтобы выключить
оборудование при обычном выходе из скрипта, используйте `finally`:

```python
import time
import api as ship

ship.start()
prop = ship.Propulsion("propulsion_0")
rcs = ship.RCS("rcs_2")

try:
    prop.throttle(0.2)
    while ship.is_running():
        time.sleep(0.1)
finally:
    if ship.is_running():
        prop.throttle(0)
        rcs.gyro(0)
        rcs.setThrust((0, 0))
        ship.command("disable", module="drill_3")
```

Этот пример выключает ускорение и вращение; уже набранная линейная скорость
сохраняется. Новому скрипту следует явно задавать нужные состояния модулей.
