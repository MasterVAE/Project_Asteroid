# Project Asteroid

C++-сервер мира и клиенты его WebSocket API.

```text
backend/include/        Модель мира и интерфейс сервера
backend/src/            Мир, WebSocket-сервер, обработчики JSON
frontend/python/        Консольный Python-клиент
frontend/browser/       Браузерный API и полноэкранная карта без зависимостей
Makefile                Сборка сервера в build/app
```

## Запуск сервера на удалённом компьютере

Нужны C++17, make и Boost с библиотекой Boost.JSON. Например, на Ubuntu:

```sh
sudo apt install build-essential libboost-all-dev
make
./build/app world.json
```

На macOS установите Boost командой `brew install boost`, затем выполните те же `make` и `./build/app world.json`.

Запускайте команду из корня проекта: сервер раздаёт файлы из `frontend/browser`. При запуске из другой директории передайте путь явно: `./app /path/to/world.json /path/to/frontend/browser`. На удалённый компьютер нужно скопировать и бинарник, и каталог `frontend/browser`.

Сервер слушает **0.0.0.0:8080**, обслуживает HTTP и WebSocket на одном порту. Разрешите входящий **TCP 8080** в firewall ОС и правилах облачного провайдера; если компьютер за роутером, настройте проброс порта. Клиенту нужен доступный IP или DNS-адрес сервера. `localhost` в браузере означает компьютер пользователя, а не удалённый сервер.

Сейчас `LoadWorld` создаёт случайный мир из 100 астероидов и 10 кораблей; содержимое `world.json` ещё не загружается, отсутствие файла не мешает запуску. Мир непрерывно обновляется в основном потоке с реальным `delta_time`, HTTP и WebSocket обслуживаются в отдельном потоке.

## Браузерная карта

На своём компьютере просто откройте **http://SERVER_IP:8080**. Например, **http://46.173.218.137:8080** — если сервер запущен по адресу из Python-клиента и порт доступен. Ничего скачивать, устанавливать или запускать на клиентском компьютере не нужно.

Страница автоматически подключается к `/ws` на том же адресе и порту. Адрес можно изменить в поле подключения, если нужна карта другого сервера.

Адрес можно передать ссылкой с автоматическим подключением:

```text
http://SERVER_IP:8080/?server=ws%3A%2F%2FOTHER_SERVER_IP%3A8080
```

При каждом открытии страницы клиент подключается к её серверу (или к адресу из `?server=...`); при разрыве повторяет подключение с интервалом до 10 секунд. «Отключить» останавливает переподключение. Последняя карта сохраняется на экране, статус показывает потерю связи.

Карта занимает весь размер окна. Астероиды показаны коричневым, корабли — голубым. Перетаскивайте карту мышью или пальцем, меняйте масштаб колесом или кнопками `+`/`−`, нажмите «Вся карта» для обзора всех объектов. Клик по объекту показывает координаты, скорость, ресурсы или модули. После фокусировки карты доступны стрелки, `+`, `−` и `F`. Кнопка «Полный экран» скрывает интерфейс браузера, если браузер поддерживает этот режим.

Клиент получает карту раз в секунду и плавно интерполирует положение и направление кораблей между снимками через `requestAnimationFrame`. Отображение отстаёт примерно на один интервал обновления; при потере связи корабли останавливаются на последней отображённой позиции. Клики учитывают видимую позицию корабля.

HTML, CSS и JavaScript раздаёт сам C++-сервер. Node.js, Python и сборка фронтенда не нужны. При желании файлы клиента можно разместить отдельно на статическом HTTP-сервере, указав WebSocket-адрес через `?server=...`. Открывайте клиент через HTTP/HTTPS, а не через `file://`, поскольку используются JS-модули.

## HTTPS и удалённый доступ через WSS

Страница, открытая по **HTTPS**, должна подключаться по **wss://**. Текущий C++-сервер TLS не поддерживает; перед ним нужен reverse proxy с действительным сертификатом. Например, конфигурация Nginx на том же удалённом компьютере (пути сертификата замените своими):

```nginx
server {
    listen 443 ssl;
    server_name asteroid.example.com;

    ssl_certificate     /etc/letsencrypt/live/asteroid.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/asteroid.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 60s;
    }
}
```

Откройте TCP 443 и перейдите на **https://asteroid.example.com**: Nginx передаст серверу и HTTP-запросы файлов, и WebSocket, клиент автоматически выберет **wss://asteroid.example.com/ws**. Внешний доступ к 8080 можно закрыть firewall: Nginx обращается к нему локально. Без TLS достаточно ссылки **http://SERVER_IP:8080**.

Если сервер недоступен из интернета, можно использовать SSH-туннель:

```sh
ssh -N -L 18080:127.0.0.1:8080 user@SERVER_IP
```

Оставьте SSH запущенным и откройте **http://localhost:18080**: страница и WebSocket работают через один туннель. Для этого достаточно доступного SSH-порта, открывать 8080 наружу не требуется.

## Использование JavaScript API

`frontend/browser/asteroidAPI.js` экспортирует независимый класс для браузера:

```js
import { AsteroidAPI } from './asteroidAPI.js';

const api = new AsteroidAPI();
try {
  await api.connect('ws://SERVER_IP:8080');
  const map = await api.getMap();
  console.log(map.entities);
  if (map.entities.length) {
    console.log(await api.getEntity(map.entities[0].id));
  }
} catch (error) {
  console.error(error.message);
} finally {
  api.disconnect();
}
```

`connect`, `getMap`, `getEntity` возвращают Promise. API последовательно отправляет запросы, поскольку сервер не передаёт идентификаторы запросов. Тайм-аут подключения — 8 секунд, ответа — 5 секунд; закрытие соединения отклоняет ожидающие запросы. Событие `close` сообщает о внешнем разрыве; переподключение и опрос раз в секунду реализованы в `app.js`.

Запрос карты:

```json
{"type":"request","request_type":"get_map"}
```

Ответ содержит `entities`: у каждого объекта есть `id`, `type` (`asteroid`/`craft`), `position: {x,y}`, `velocity: {x,y}`. Запрос `{"type":"request","request_type":"get_entity","entity_id":1}` возвращает объект с ресурсами `resources` для астероида или модулями `modules` для корабля. Числовые типы модулей: `0` — добыча, `1` — производство, `2` — хранилище. Текстовое приветствие `Your ID: ...` API пропускает.

Для просмотра подробностей обновите и пересоберите сервер: в ответы добавлен `id`. Со старым сервером карта отображается, но запрос деталей по клику недоступен.
