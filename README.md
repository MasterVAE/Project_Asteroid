# Project Asteroid

Двумерный прототип космической симуляции на C++17 и SFML 3. Корабли
управляются отдельными Python-скриптами через JSON-протокол. Реализованы
движение, сканирование, добыча, хранение и передача ресурсов, генерация энергии.

## Сборка

Нужны CMake **3.24+** и компилятор C++17: Apple Clang на macOS,
GCC/Clang на Linux или Visual Studio 2022 (компонент Desktop development with C++)
на Windows. Python 3 нужен **при запуске** скриптов корабля; для компиляции игры
он не требуется. Python должен быть в `PATH` (`python3`, на Windows также `python`).

Есть два режима работы с зависимостями:

- По умолчанию используются установленные **SFML 3.x** и **Boost 1.87+**
  (компоненты JSON, Filesystem, Process v2). SFML 2.x не подходит.
- `ASTEROID_FETCH_DEPENDENCIES=ON` скачивает и собирает **SFML 3.0.2** и
  **Boost 1.87.0** статически тем же компилятором, что и игру. На Windows/macOS
  SFML также собирает FreeType 2.13.2. Первой сборке нужен интернет.
  Для загрузки FreeType нужен Git (на Windows установите Git for Windows).
  Исходники и результаты зависимостей кешируются в каталоге сборки.

### macOS

```sh
xcode-select --install  # если Command Line Tools ещё не установлены
brew install cmake sfml boost
make                   # build/release/bin/Release/app
make run               # запуск из корня проекта, где находится scripts/
make debug             # build/debug/bin/Debug/app
make run-debug
make sanitize          # отдельная Debug-сборка с ASan и UBSan
make run-sanitize
```

Makefile вызывает CMake и не зависит от Homebrew. CMake обычно сам находит
библиотеки Homebrew; при нестандартном размещении задайте
`CMAKE_ARGS='-DCMAKE_PREFIX_PATH=/путь/к/зависимостям'`.

### Linux

Сборка выполняется непосредственно на Linux-машине. Например, на Ubuntu 24.04
установите компилятор и системные зависимости SFML,
затем соберите SFML и Boost из закреплённых исходников:

```sh
sudo apt-get update
sudo apt-get install build-essential cmake git ninja-build xz-utils \
  libfreetype-dev libx11-dev libxrandr-dev libxcursor-dev libxi-dev \
  libudev-dev libgl1-mesa-dev python3
make standalone
cmake --build build/standalone --target run
```

Если подходящие SFML и Boost уже установлены, достаточно `make` / `make run`.
Результат собирается для архитектуры этой Linux-машины. При переносе на другую
машину нужны совместимые версии glibc, libstdc++, X11, OpenGL, udev и FreeType.

### Windows

В Developer PowerShell для Visual Studio 2022, из корня проекта:

```powershell
cmake --preset standalone
cmake --build --preset standalone --parallel 4
cmake --build build/standalone --config Release --target run
```

Результат: `build/standalone/bin/Release/app.exe`. Make для Windows не нужен.
При работе с готовыми зависимостями используйте preset `release` и задайте
`-DCMAKE_PREFIX_PATH=...` или toolchain vcpkg. Архитектура, компилятор и тип
runtime готовых библиотек должны совпадать с настройками приложения.

### CMake без Makefile

```sh
cmake --preset release
cmake --build --preset release --parallel 4
cmake --preset debug
cmake --build --preset debug --parallel 4
```

Также доступны presets `sanitize`, `standalone`, `windows-mingw`. Каждый
использует отдельный каталог `build/`. Можно выбрать Ninja, Xcode или Visual


### С macOS под Windows (MinGW-w64)

```sh
brew install cmake mingw-w64
make windows                  # build/windows-mingw/bin/Release/app.exe
```

Команда использует `cmake/toolchains/windows-mingw-x64.cmake`: SFML и Boost

Архив с исполняемым файлом, скриптами и лицензиями создаётся командой:

Поддерживаемые цели с Mac: Windows x64 и macOS.
Для другой архитектуры macOS используйте отдельный каталог и сборку зависимостей
из исходников, например на Apple Silicon для Intel:

```sh

cmake --build build/macos-x64 --parallel 4
```

На Windows нужен OpenGL-драйвер и Python 3 для скриптов. Python не включается
в дистрибутив. На macOS минимальную версию ОС задаёт используемая версия SFML
и SDK; подпись приложения и notarization выполняются отдельно.

## Начальный мир и интерфейс

При запуске без аргументов создаются:

- 10 кораблей с ID `0`–`9`, расположенных в `(0, 0)`, `(30, 0)`, …, `(270, 0)`.
  Начальные скорости, углы и угловые скорости равны нулю.
- 50 неподвижных астероидов с ID `10`–`59` и случайными координатами X и Y
  от `-1000` до `1000`.
- В каждом астероиде суммарно от **1 до 10 единиц** ресурсов. Для каждой единицы
  независимо выбирается случайный тип из таблицы ниже. После добычи последней
  единицы астероид ставится на удаление в конце обновления мира.

| Тип C++ | Имя в API |
| --- | --- |
| `SILICON` | `silicon` |
| `CARBON` | `carbon` |
| `IRON` | `iron` |
| `ICE` | `ice` |
| `COPPER` | `copper` |
| `GOLD` | `gold` |

Каждый корабль получает по одному модулю в порядке: `PROPULSION`, `STORAGE`,
`RCS`, `DRILL`, `SCAN`, `POWER`. Их имена: `prop_0`, `stor_1`, `rcs_2`,
`drill_3`, `scan_4`, `power_5`. Нумерация общая для всех модулей одного корабля;
при другом порядке добавления имена будут другими.

Окно по умолчанию имеет размер **800 × 600**. Выберите объект в списке слева
или нажатием на него: камера будет следовать за ним. Для корабля появится поле
пути к скрипту. Введите, например, `scripts/script.py` и нажмите Enter.
Повторный запуск останавливает предыдущий скрипт этого корабля. Автоматически
скрипты не запускаются.

Без выбранного объекта и вне полей ввода камера перемещается клавишами WASD
со скоростью 300 единиц мира в секунду. Escape снимает фокус ввода; вне
активной консоли также сбрасывает выбор объекта. Колесо над списком объектов
прокручивает список, над нижней панелью — историю вывода.

Нажмите на нижнюю консоль, введите строку и нажмите Enter. Она передаётся
скрипту выбранного корабля как событие `console_message`. Если в мире только
один корабль, выбор для отправки сообщения необязателен. Стрелки ↑/↓ перебирают
историю команд. Поля поддерживают стрелки, Home/End, Backspace/Delete и Ctrl/Cmd+V.

В консоли сохраняется до **1000 строк**: новые вытесняют старые. Строки длиннее
примерно 4096 байт разбиваются. Временный файл захвата периодически очищается
после чтения 4 МиБ вывода.

## Характеристики модулей по умолчанию

Значения определены в [`modules.hpp`](backend/include/modules.hpp),
[`modules.cpp`](backend/src/modules.cpp) и [`game.cpp`](backend/src/game.cpp).
Время измеряется в секундах симуляции, расстояние — в единицах мира,
энергия — в условных единицах заряда.

| Модуль C++ / тип | Имя в начальном мире | Характеристики | Начальное состояние | Расход энергии |
| --- | --- | --- | --- | --- |
| `PropulsionModule` / `PROPULSION` | `prop_0` | Максимальное ускорение вперёд **10 ед./с²**; доля тяги от **0 до 1** | Тяга **0** | Не реализован |
| `StorageModule` / `STORAGE` | `stor_1` | Общая вместимость **20 единиц** любых ресурсов; передача **1 единицы** за команду на расстоянии **≤ 10** | Пустой; приём отключён | Не реализован |
| `RCSModule` / `RCS` | `rcs_2` | Максимальное ускорение **1 ед./с²**; максимальная угловая скорость **1 рад/с**; доля вращения от **−1 до 1**; длина вектора тяги **≤ 1** | Вращение **0**, тяга **(0, 0)** | Не реализован |
| `DrillModule` / `DRILL` | `drill_3` | Интервал добычи **0,5 с** работы с питанием; расстояние до центра астероида строго **< 1**; добыча **1 единицы** за срабатывание | Выключен; таймер **0** | **5 ед./с**, пока включён и получает питание |
| `ScanModule` / `SCAN` | `scan_4` | Радиус **500**, включая границу; возвращает имена и мировые координаты всех объектов, включая собственный корабль | Сканирование только по запросу | **30 единиц за сканирование** |
| `PowerModule` / `POWER` | `power_5` | Ёмкость **100**; генерация **5 ед./с**; заряд ограничен ёмкостью | Заряд **100** | Генерирует энергию |

Для каждого типа в `MODULES_DATA` указана масса **1**. Сейчас эта масса
не участвует в расчёте движения. Вместимость 20 задаётся при
`Craft::AddModule(STORAGE)`; конструктору склада можно передать другую вместимость.

### Питание

Сканер и бур ищут на своём корабле модули типа `POWER`. Они перебирают их
в порядке установки и списывают заряд с первого, который может целиком оплатить
операцию. Заряд нескольких источников для одной операции не суммируется.

`PowerModule::TakeCharge(amount)` возвращает `true` при успешном списании.
При недостатке заряда, отрицательном или неконечном аргументе возвращает `false`
и не меняет заряд.

Сканирование без доступных 30 единиц энергии возвращает **пустой список**.
Отдельного признака «нет питания» в ответе нет. Генератор восстанавливает
30 единиц за 6 секунд при отсутствии других потребителей. Сканирование каждые
0,5 секунды требует примерно 60 ед./с и быстро исчерпывает начальные 100 единиц.

Включённый бур запрашивает `5 * delta_time` единиц за обновление. Только после
успешного списания его таймер увеличивается на `delta_time`. Без питания таймер
сохраняет накопленное значение; при выключении или отсутствии мира сбрасывается.
Энергия расходуется и при отсутствии доступного астероида или места в складе.
За обновление выполняется не больше одной попытки добычи; после срабатывания
таймер сбрасывается в ноль.

## Управление кораблём из Python

API находится в [`scripts/api.py`](scripts/api.py). Python запускается игрой
для выбранного корабля; скрипты с этим API предназначены для работы внутри игры.
Вызовите `ship.start()` один раз и работайте, пока `ship.is_running()` возвращает
`True`. `stdin` занят протоколом. При импорте `api` обычный `print()`
перенаправляется в игровую консоль; `sys.stderr`, logging и traceback также
попадают в неё. Служебные сообщения отправляются через сохранённый поток `stdout`.

Минимальный пример:

```python
import time
import api as ship

ship.start()
print(ship.getModules())
# ["prop_0", "stor_1", "rcs_2", "drill_3", "scan_4", "power_5"]

storage = ship.Storage("stor_1")
power = ship.Power("power_5")
print("Инвентарь:", storage.getStorage())
print("Энергия:", power.getCharge(), "/", power.getCapacity())

while ship.is_running():
    time.sleep(0.1)
```

Имена классов обёрток сейчас: **`Propulsion`, `Storage`, `RCS`, `Power`**.
Они принимают имя установленного модуля и не проверяют его наличие.
Для бура и сканера отдельных Python-классов пока нет: используйте
`ship.command()` и внутренний помощник `ship._request()`.

### Чтение состояния

| Вызов | Пример результата |
| --- | --- |
| `ship.getId()` | `0` |
| `ship.getPos()` | `(50.0, 50.0)` |
| `ship.getVel()` | `(1.0, 0.0)` |
| `ship.getAngle()` | `1.57` |
| `ship.getAngularVelocity()` | `0.5` |
| `ship.getModules()` | `["prop_0", "stor_1", "rcs_2", "drill_3", "scan_4", "power_5"]` |
| `ship.Propulsion("prop_0").getMaxThrottle()` | `10.0` |
| `ship.RCS("rcs_2").getMaxGyro()` | `1.0` |
| `ship.RCS("rcs_2").getThrust()` | `1.0` |
| `ship.Storage("stor_1").getStorage()` | `{}` или `{"silicon": 3, "iron": 1}` |
| `ship.Power("power_5").getCapacity()` | `100.0` |
| `ship.Power("power_5").getCharge()` | `100.0` при полном заряде |

Запросы состояния корабля, параметров двигателей и питания принимают
`timeout=2.0`. У `Storage.getStorage()` отдельного аргумента тайм-аута нет;
он использует стандартные 2 секунды внутреннего `_request()`.
При тайм-ауте возникает `TimeoutError`, при ответе с `error` или закрытии
соединения — `RuntimeError`. Ошибочные запросы к модулям могут только попасть
в журнал и завершиться для Python по тайм-ауту.

Координаты и скорость можно распаковать: `x, y = ship.getPos()`,
`vx, vy = ship.getVel()`.

### Основной двигатель и RCS

```python
prop = ship.Propulsion("prop_0")
rcs = ship.RCS("rcs_2")

prop.throttle(0.3)
rcs.gyro(-0.5)
rcs.setThrust((0, 0.5))

# Чтобы выключить тягу и вращение:
prop.throttle(0)
rcs.gyro(0)
rcs.setThrust((0, 0))
```

`prop.throttle(value=1.0)` задаёт долю основной тяги от 0 до 1.
`rcs.gyro(value=1.0)` задаёт долю угловой скорости от −1 до 1.
Значения вне диапазонов игнорируются.

`rcs.setThrust(value=(0, 0))` принимает пару конечных чисел. X направлена вперёд
по кораблю, Y — влево относительно его направления. `(-1, 0)` задаёт тягу назад,
`(0, 1)` — боковую. Вектор длиной больше 1 нормализуется. Неверный размер,
тип или неконечные координаты приводят к сообщению `Invalid packet` в журнале.

В мировых координатах X направлена вправо, Y — вверх. Углы — в радианах:
0 вправо, π/2 вверх, положительное вращение — против часовой стрелки.
Ускорения основного двигателя и RCS складываются; гироскоп задаёт угловую
скорость, а не угол. Трения нет: выключение тяги сохраняет набранную скорость.
Для торможения нужна тяга против скорости.

Команды сохраняют значения до следующей команды. Скрипт должен обнулять
управление при завершении: автоматического сброса при его падении сейчас нет.

### Склад и передача ресурсов

```python
storage = ship.Storage("stor_1")
print(storage.getStorage())

# На принимающем корабле:
storage.readyForRecieve()

# На отправляющем корабле: передать одну единицу silicon кораблю с ID 8.
storage.transfer(8, "silicon")

# На принимающем корабле: отключить приём.
ship.command("not_ready_for_recieve", module=storage.name)
```

Передача выполняется только при наличии ресурса у отправителя, расстоянии
до другого корабля **не больше 10** и наличии у получателя хотя бы одного
готового к приёму склада со свободным местом. Выбирается первый подходящий
склад. Передача собственному кораблю и астероиду не выполняется. Одна команда
передаёт одну единицу; параметра количества нет. При невыполнении условий
инвентари не меняются. Подтверждение результата команды не возвращается.

Метод Python `Storage.notReadyForRecieve()` сейчас отправляет команду
с опечаткой (`not_reaady_for_recieve`). Для отключения приёма используйте
правильную команду из примера выше.

C++ API склада:

| Метод | Поведение |
| --- | --- |
| `GetInventory()` | Ссылка на карту `RESOURCE_TYPE → std::size_t` |
| `GetCapacity()` | Общая вместимость склада |
| `ResourceCount(resource)` | Количество ресурса или 0 |
| `AddToInventory({{SILICON, 5}, {IRON, 2}})` | Добавление с проверкой общей вместимости |
| `TakeFromInventory({{SILICON, 3}})` | Изъятие с проверкой всех запрошенных количеств |
| `ReadyForRecieve()` / `NotReadyForRecieve()` | Включение / отключение приёма |

При нехватке места или ресурсов `AddToInventory` и `TakeFromInventory`
выбрасывают `std::runtime_error`, сохраняя содержимое. Нулевые количества
не создают новых записей, полностью изъятые ресурсы удаляются из карты.
Изменение карты через `GetInventory()` обходит проверки. Прямые операции
с инвентарём требуют внешней синхронизации с состоянием корабля.
`StorageModule::Transfer(id, type)` пока является пустой заготовкой;
реализованная передача находится в обработчике JSON-команды `transfer`.

### Сканер

```python
objects = ship._request("scan", module="scan_4")
for obj in objects:
    print(obj["name"], obj["x"], obj["y"])
```

Ответ — список объектов вида `{"name": "Asteroid #10", "x": 100.0, "y": 50.0}`.
Имена формируются как `Craft #ID` и `Asteroid #ID`. Координаты мировые,
порядок объектов не фиксирован. При питании в список включается и собственный
корабль. Без источника питания или достаточного заряда результат пустой.

### Бур

```python
cooldown = ship._request("get_drill_cooldown", module="drill_3")["drill_cooldown"]
ship.command("enable", module="drill_3")
# После подлёта к астероиду отслеживайте поступление ресурсов через getStorage().
ship.command("disable", module="drill_3")
```

Бур выбирает первый астероид на расстоянии строго меньше 1 и добывает одну
случайную оставшуюся единицу ресурса, затем пытается разместить её в первом
складе корабля со свободным местом. Выбор астероида по ID не предусмотрен.
Энергия и таймер описаны в разделе характеристик выше.

### Доступ к модулям из C++

`Craft::GetModules()` возвращает `std::vector<Module*>` всех модулей корабля.
`Craft::GetModulesOfType(MODULE_TYPE::POWER)` возвращает такой же список,
отфильтрованный по типу; при отсутствии модулей список пустой. Владельцем
модулей остаётся корабль. `Craft::AddModule(type)` создаёт модуль, присваивает
ему имя и возвращает `Module&`. Поддерживаются все шесть типов из таблицы.

## Протокол и события

Обмен идёт JSON-объектами по одному на строку (`\n`) через стандартные потоки
Python. Поле `module` содержит `"none"` для корабля или имя модуля.

| Получатель | Методы запросов (`request`) | Методы команд (`command`) |
| --- | --- | --- |
| Корабль (`"none"`) | `get_id`, `get_position`, `get_velocity`, `get_angle`, `get_angular_velocity`, `get_modules` | Нет реализованных команд |
| `prop_0` | `get_max_throttle` | `set_throttle` |
| `stor_1` | `get_storage` | `ready_for_recieve`, `not_ready_for_recieve`, `transfer` |
| `rcs_2` | `get_max_gyro`, `get_max_thrust` | `set_gyro`, `set_thrust` |
| `drill_3` | `get_drill_cooldown` | `enable`, `disable` |
| `scan_4` | `scan` | — |
| `power_5` | `get_capacity`, `get_charge` | — |

Примеры запросов, ответов и команд:

```json
{"type":"request","id":1,"module":"none","method":"get_position"}
{"type":"response","id":1,"result":{"x":0.0,"y":0.0}}
{"type":"command","module":"prop_0","method":"set_throttle","value":0.3}
{"type":"request","id":2,"module":"stor_1","method":"get_storage"}
{"type":"response","id":2,"result":[{"resource":"silicon","count":3}]}
{"type":"command","module":"stor_1","method":"transfer","value":[8,"silicon"]}
{"type":"request","id":3,"module":"scan_4","method":"scan"}
{"type":"response","id":3,"result":[{"name":"Craft #0","x":0.0,"y":0.0},{"name":"Asteroid #10","x":100.0,"y":50.0}]}
{"type":"request","id":4,"module":"power_5","method":"get_charge"}
{"type":"response","id":4,"result":{"charge":70.0}}
{"type":"command","module":"drill_3","method":"enable"}
{"type":"event","name":"console_message","data":"любая строка из консоли"}
{"type":"shutdown"}
```

Ответ сопоставляется запросу по `id`; вместо `result` может прийти поле `error`.
Команды не ожидают подтверждения. Запрос к отсутствующему модулю завершится
по тайм-ауту, команда к нему будет пропущена. `shutdown` или EOF снимают
флаг `is_running()` и завершают ожидающие запросы с ошибкой.

Обработчики событий выполняются в отдельном потоке. Регистрируйте их
до `ship.start()`; для каждого имени действует один обработчик:

```python
@ship.on("console_message")
def console_message(message):
    print(f"Получена команда: {message}")
```

Автоматического события обнаружения астероида или получения ресурса нет:
состояние нужно запрашивать. Произвольные события можно отправлять из C++
через `Craft::SendEvent()`.

## Текущее состояние и ограничения

- Загрузка мира из файла пока не реализована: `World(filename)` пустой.
  Запускайте игру без аргумента пути к миру.
- [`scripts/script.py`](scripts/script.py) показывает инвентарь и отправляет
  одну команду передачи ресурса кораблю с ID 8. Успех зависит от наличия ресурса,
  расстояния и готовности принимающего склада.
- [`scripts/miner.py`](scripts/miner.py) и [`scripts/move.py`](scripts/move.py)
  пока обращаются к старому имени `ship.Prop`, которого больше нет в API.
  Майнер также сканирует каждые 0,5 секунды и принимает отсутствие энергии
  за исчезновение цели; текущему питанию такой режим не соответствует.
- При заполненных складах бур всё равно извлекает ресурс из астероида,
  поэтому добыча, для которой не нашлось места, теряется.
- При одновременном бурении одного астероида несколькими кораблями возможен
  повторный вызов добычи после его исчерпания до удаления в конце кадра.
  Проверки пустого астероида в `Mine()` пока нет, это может привести к падению.
- Доступ сканера к контейнеру объектов мира не синхронизирован с удалением
  объектов основным потоком; при параллельном сканировании и добыче возможно падение.
- При аварийном завершении скрипта игра не сбрасывает тягу, вращение и состояние
  бура. Новому скрипту следует явно устанавливать нужные значения управления.
