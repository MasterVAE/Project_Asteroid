# Регистрация и единый API

Браузер и Python используют один обработчик команд, одинаковые поля запросов,
результаты и ошибки. HTTP: `POST /api`; игровые запросы также работают по `/ws`.
Регистрация и операции аккаунта идут через HTTP. Перед каждым игровым запросом
сервер проверяет действительность сессии или API-ключа, независимо от транспорта.

## Запуск на сервере

Установите зависимости и пересоберите приложение:

```sh
sudo apt update
sudo apt install build-essential pkg-config libboost-all-dev libssl-dev libsqlite3-dev
make
ASTEROID_PUBLIC_ORIGIN=https://46.173.218.137 ./build/app world.json
```

`ASTEROID_PUBLIC_ORIGIN` — точный origin без завершающего `/`: схема, адрес и,
при нестандартном порте, порт. В systemd задайте его через `Environment=`.
Приложение слушает только `127.0.0.1:8080`. В Nginx сохраните передачу `Host`,
`X-Forwarded-Proto`, `X-Real-IP`, `Upgrade` и `Connection`, настроенную для HTTPS/WSS.
`Host` должен сохранять нестандартный публичный порт, если он используется.
Обычный `https://46.173.218.137` работает с текущим `proxy_set_header Host $host`.

Для macOS: `brew install boost openssl sqlite pkg-config`, затем `make`.

Аккаунты, сессии и ключи сохраняются в `data/auth.sqlite3`. Настройка
`ASTEROID_AUTH_DB=/absolute/path/accounts.sqlite3` задаёт другой путь. Храните БД
на постоянном диске и делайте защищённые резервные копии; SQLite может использовать
соседние файлы `-wal` и `-shm`. База и её содержимое не входят в git.

Локальная разработка требует явного включения HTTP:

```sh
ASTEROID_PUBLIC_ORIGIN=http://127.0.0.1:8080 ASTEROID_DEV_AUTH=1 ./build/app world.json
```

Открывайте ровно этот адрес. Такой режим разрешён только для `localhost:8080`
и `127.0.0.1:8080`. На публичном сервере оставьте HTTPS и не задавайте DEV_AUTH.

## Вход на сайте

Откройте публичный HTTPS-адрес и нажмите «Создать аккаунт». Логины регистронезависимы:
3–32 латинские буквы, цифры, `_` и `-`. Пароль — минимум 12 байт (форма требует
12 символов), максимум 1024 байта. После регистрации вход выполняется сразу.
Перезагрузка страницы восстанавливает сессию. Выход отзывает текущую сессию и
закрывает связанные WebSocket-соединения. Другие сессии остаются активными.

Сессия действует 24 часа. В production используется cookie
`__Host-asteroid_session; Secure; HttpOnly; SameSite=Strict; Path=/`.
JavaScript не читает токен; localStorage/sessionStorage для секретов не используются.
Браузер работает с API того же origin. Параметр `?server=` больше не переключает
сайт на чужой сервер: для другого сервера откройте его собственный сайт.

В разделе «API-ключи» создайте отдельный ключ для бота, подтвердив пароль.
Ключ показывается полностью только один раз, действует 1–365 дней и имеет доступ
к чтению игры (`game:read`), но не к управлению аккаунтом и другими ключами.
Одновременно допускается до 20 действующих API-ключей. Их можно отзывать отдельно;
выход из браузера не отзывает ключи. Для прекращения работы бота отзовите его ключ.

## Одинаковые методы SDK

| Метод | Назначение |
|---|---|
| `register(username, password)` | Создать аккаунт и браузерную/клиентскую сессию |
| `login(username, password)` | Войти; текущая переданная сессия заменяется |
| `me()` | Получить профиль |
| `connect()` / `disconnect()` | Открыть / закрыть игровой WebSocket |
| `getMap()` / `getEntity(id)` | Прочитать карту / объект |
| `createApiKey(name, password, expiresDays=30)` | Выпустить ключ после подтверждения пароля |
| `listApiKeys()` / `revokeApiKey(id)` | Список / отзыв собственных ключей |
| `logout()` | Отозвать текущую сессию (для API-ключа используйте `disconnect`) |

В JS методы асинхронные, в Python — синхронные. `getMap` и `getEntity` используют
WebSocket при подключении, иначе HTTP. Новые игровые команды добавляются в один
диспетчер `backend/src/api.cpp`, а не в два отдельных обработчика клиентов.

### Python

```sh
python3 -m pip install -r frontend/python/requirements.txt
```

Импорт модуля не запускает сеть или консольный ввод:

```python
import os
from frontend.python.asteroidAPI import AsteroidAPI

api = AsteroidAPI('https://46.173.218.137', api_key=os.environ['ASTEROID_API_KEY'])
print(api.me())
api.connect()
try:
    print(api.getMap())
    print(api.getEntity(1))
finally:
    api.disconnect()
```

Ключ задавайте через защищённое окружение процесса или хранилище секретов,
а не в исходниках, URL или аргументах командной строки. TLS-проверки включены.

Логин и регистрация доступны и Python-клиенту. Например, интерактивный запуск:

```sh
python3 frontend/python/asteroidAPI.py --username alice
python3 frontend/python/asteroidAPI.py --username alice --register
```

Пароль вводится через `getpass`. При наличии `ASTEROID_API_KEY` CLI использует ключ.
Python хранит cookie только в памяти; `disconnect()` закрывает сеть, `logout()`
отзывает сессию. Для другого сервера используйте `--server https://...`.

### JavaScript

```js
import { AsteroidAPI } from './asteroidAPI.js';
const api = new AsteroidAPI();
await api.login(username, password);
await api.connect();
const map = await api.getMap();
await api.logout();
```

## Контракт протокола

HTTP-запросы отправляются с заголовками `Content-Type: application/json` и
`X-Asteroid-Client: 1`. Python-бот передаёт ключ в `Authorization: Bearer ...`;
сессии используют cookie. При наличии Authorization он имеет приоритет над cookie.
В браузерном WebSocket cookie передаётся при handshake, Python может передать
Authorization. В URL и в каждом игровом сообщении секрет повторять не требуется.

Запрос карты, одинаковый для HTTP и WebSocket:

```json
{"type":"request","request_type":"get_map"}
```

Успешный ответ:

```json
{"ok":true,"result":{"entities":[]}}
```

Ошибка:

```json
{"ok":false,"error":{"status":401,"code":"AUTH_REQUIRED","message":"Войдите в аккаунт."}}
```

Поля операций аккаунта:

| `request_type` | Поля |
|---|---|
| `register`, `login` | `username`, `password` |
| `me`, `logout`, `list_api_keys` | Нет |
| `create_api_key` | `name`, `password`, `expires_days` (1–365) |
| `revoke_api_key` | `key_id` |
| `get_entity` | `entity_id` |

Успех register/login возвращает профиль и устанавливает cookie, но не отдаёт
сессионный токен в JSON. Ошибки всегда имеют единый конверт; HTTP также возвращает
соответствующий статус. WebSocket пока обслуживает запросы последовательно,
поэтому SDK сериализуют отправку/получение. Текстовое приветствие `Your ID: ...`
сохраняется, SDK пропускают его. Старые клиенты без входа больше не подключаются;
после обновления сервера обновите и оба клиента.

## Меры защиты и границы текущей реализации

Пароли хешируются OpenSSL scrypt (`N=2^17, r=8, p=1`) с независимой случайной солью.
Сессионные токены и ключи содержат 256 бит случайности; БД хранит SHA-256-дайджесты,
а не исходные токены. Два рабочих потока выполняют операции аккаунта; вывод паролей
и ключей в логи отсутствует. Хеширование пароля требует около 128 МиБ на операцию
и выполняется вне mutex мира. Нужна память для двух параллельных операций.

Origin проверяется по точному публичному адресу, POST требует JSON и специальный
заголовок, разрешения CORS не выдаются. Для native-клиентов допускается отсутствие
Origin; владение действующим ключом/cookie остаётся обязательным. Backend доверяет
X-Forwarded-Proto и X-Real-IP только за счёт локальной привязки и контролируемого
reverse proxy. Не открывайте backend наружу.

Вход, регистрация и создание ключей ограничены 10 попытками в минуту по IP и
аккаунту; очередь HTTP-запросов ограничена. Отзыв/выход закрывает связанные
соединения, истечение проверяется на каждом запросе и каждые 15 секунд простоя.

Пока реализованы аккаунты и доступ к общей карте. Модели компаний, принадлежности
кораблей и команд изменения мира ещё нет. При добавлении этих команд потребуется
проверять владельца и отдельные разрешения и для сессии, и для ключа. Восстановление
пароля, подтверждение почты и MFA в этот этап не входят.

## Проверка

```sh
make
python3 tests/test_auth.py -v
```

Тест запускает временный сервер на свободном `127.0.0.1:8080` и использует отдельную
БД. Проверяет регистрацию, вход, оба транспорта, ошибки, отзыв ключей, logout,
разделение пользователей, истечение, перезапуск, лимиты и production cookie.
Публичный сервер не затрагивается.
