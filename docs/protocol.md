# Бинарный протокол

Адрес: `/ws`. Каждый бинарный WebSocket message содержит ровно один пакет.
JSON, разделителей и дополнительной оболочки нет. Лимит сообщения — 1 МиБ + 4096 байт
(1 052 672 байта), чтобы вместить большую строку вместе с типом пакета и другими полями.
WebSocket-фреймы, фрагментацию и ping/pong обрабатывает Boost.Beast.

Типы: `u8` — 1 байт, `u16` — 2, `u32` — 4, `f32` — IEEE-754 float32. Числа little-endian.
`string` = длина UTF-8 в байтах (`u16`) + сами UTF-8 байты, без завершающего нуля.
`long_string` = длина UTF-8 в байтах (`u32`) + сами UTF-8 байты, без завершающего нуля.
Лимит `long_string` — 1 МиБ (1 048 576 байт), включительно; пустая строка допустима.
Лимит считается по байтам UTF-8, а не по символам. Длина сверх лимита и неполные
данные отклоняются при чтении; запись строки сверх лимита также вызывает ошибку.
Обычный `string` сохраняет формат и лимит 65 535 байт; пакеты авторизации не меняются.

| Направление | Первый байт | Следующие поля по порядку |
|---|---|---|
| Клиент → сервер: вход | 1 | username:string, password:string |
| Клиент → сервер: регистрация | 2 | username:string, password:string |
| Клиент → сервер: выход | 3 | нет |
| Клиент → сервер: прикрепить и запустить скрипт | 4 | craft_id:u32, source:long_string |
| Клиент → сервер: остановить скрипт | 5 | craft_id:u32 |
| Клиент → сервер: состояние и журнал скрипта | 6 | craft_id:u32 |
| Сервер → клиент: результат входа/регистрации | 128 | status:u8, user_id:u32, username:string, message:string |
| Сервер → клиент: выход выполнен | 129 | нет |
| Сервер → клиент: снимок мира (каждые 100 мс) | 130 | count:u32, count × craft |
| Сервер → клиент: состояние скрипта | 131 | craft_id:u32, state:u8, log:string |
| Сервер → клиент: ошибка пакета/сервера | 255 | message:string |

Статусы: `0` — успех, `1` — неверные поля, `2` — логин занят,
`3` — неверный логин/пароль, `4` — зарезервирован для ошибки авторизации на сервере.
При неуспешной авторизации `user_id=0`, `username` пустой, `message` содержит причину.
Логин чувствителен к регистру; ограничения — 1–64 байта без пробелов и NUL,
пароль — 8–256 байт. На браузерной стороне длина символов дополнительно
ограничена формой, окончательные ограничения в байтах проверяет сервер.

Регистрация сразу авторизует соединение. Выход и закрытие сокета сбрасывают
его авторизацию. Одновременный вход одного игрока с двух подключений отклоняется
ошибкой `255`; первое подключение остаётся авторизованным.
Одновременно отправляется один запрос; request ID пока не нужен. Снимки мира приходят
независимо от запросов и не сбрасывают ожидание ответа на клиенте. Все WebSocket-записи
соединения сериализованы; медленные потребители отключаются при очереди свыше 4 МиБ.
Снимки получают все соединения, включая гостей. При входе каждый игрок получает одно
стартовое судно; суда отключённых игроков также присутствуют в мире.

`craft` = `id:u32, owner_id:u32, owner_name:string, x:f32, y:f32,
vx:f32, vy:f32, modules:u32, script_state:u8`.

Состояния скрипта: `0` — нет, `1` — запускается, `2` — работает, `3` — остановлен,
`4` — завершён, `5` — ошибка. Ответ `131` на загрузку подтверждает принятие;
запуск асинхронный, итоговое состояние приходит в снимках. Журнал можно запросить
пакетом `6`. Пакеты `4–6` разрешены только авторизованному владельцу судна;
остальные получают `255`. Скрипт продолжает работать после выхода игрока.

Расширяйте `handle_packet` и проверяйте владельца под `world.mutex`.
См. [игроки и подключения](players.md) и [Python-скрипты](scripts.md).

Пример добавления поля ответа: добавьте поле в `AuthResponse`, запись
`out.u32(...)` в C++ `encode`, затем чтение `packet.u32()` в JS `decodeResponse`
в том же месте относительно остальных полей.

Для большого текстового поля используйте `out.long_string(text)` и
`reader.long_string()` в C++, `packet.longString(text)` и `packet.longString()`
в JavaScript. Поле используется для загрузки исходного кода в пакете `4`.
Весь пакет, включая остальные поля, должен укладываться в лимит сообщения.
