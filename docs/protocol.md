# Бинарный протокол

Адрес: `/ws`. Каждый бинарный WebSocket message содержит ровно один пакет.
JSON, разделителей и дополнительной оболочки нет. Лимит сообщения — 4096 байт.
WebSocket-фреймы, фрагментацию и ping/pong обрабатывает Boost.Beast.

Типы: `u8` — 1 байт, `u16` — 2, `u32` — 4. Числа little-endian.
`string` = длина UTF-8 в байтах (`u16`) + сами UTF-8 байты, без завершающего нуля.

| Направление | Первый байт | Следующие поля по порядку |
|---|---|---|
| Клиент → сервер: вход | 1 | username:string, password:string |
| Клиент → сервер: регистрация | 2 | username:string, password:string |
| Клиент → сервер: выход | 3 | нет |
| Сервер → клиент: результат входа/регистрации | 128 | status:u8, user_id:u32, username:string, message:string |
| Сервер → клиент: выход выполнен | 129 | нет |
| Сервер → клиент: ошибка пакета/сервера | 255 | message:string |

Статусы: `0` — успех, `1` — неверные поля, `2` — логин занят,
`3` — неверный логин/пароль, `4` — зарезервирован для ошибки авторизации на сервере.
При неуспешной авторизации `user_id=0`, `username` пустой, `message` содержит причину.
Логин чувствителен к регистру; ограничения — 1–64 байта без пробелов и NUL,
пароль — 8–256 байт. На браузерной стороне длина символов дополнительно
ограничена формой, окончательные ограничения в байтах проверяет сервер.

Регистрация сразу авторизует соединение. Выход и закрытие сокета сбрасывают
его авторизацию. Одновременно отправляется один запрос; request ID пока не нужен.
Игровых сообщений пока нет. Для них добавьте тип запроса, декодирование полей
и ветку в `handle_packet`; перед выполнением проверяйте `session.user_id != 0`.

Пример добавления поля ответа: добавьте поле в `AuthResponse`, запись
`out.u32(...)` в C++ `encode`, затем чтение `packet.u32()` в JS `decodeResponse`
в том же месте относительно остальных полей.
